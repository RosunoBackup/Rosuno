**Registration password policy — owner-adopted D-01, amended 2026-10-16.** Require at least **15 Unicode code points** (`Array.from(password).length` or provably equivalent count, not UTF-16 units, grapheme count, or UTF-8 byte count). Reject ill-formed Unicode strings, e.g. unpaired UTF-16 surrogates, rather than silently replacing them in transport. **Reject individual emojis and emoji sequences**, including native emoji presentation, variation-selector emoji, regional-indicator flags, keycaps, skin-tone combinations, ZWJ sequences and tag-sequence flags; use explicit Unicode-aware, version-tested sequence/property handling: reject all RGI emoji strings, individual default-emoji-presentation code points, explicitly emoji-styled text sequences (VS16), and emoji components combined in non-RGI flags, modifiers, keycaps, tags or joined sequences. Treat uncovered ambiguous classifications as a STOP/test-definition issue, not permission for an unsupported partial filter. If the installed Node/runtime Unicode support cannot implement the approved rule faithfully **without an unapproved dependency**, STOP. Permit ordinary Unicode letters (accents and non-Latin scripts), spaces, punctuation, passphrases, numbers and normal symbols.
